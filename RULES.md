# AI Rules & Conventions

This document specifies the strict behavioral rules that govern the LLM operating within the **Understanding Layer** of ProjectMind. 

## 1. Zero Hallucination Policy

The LLM is strictly forbidden from hallucinating files, classes, or relationships that are not explicitly present in the provided `DiffManifest` or `StructuralGraphDiff`.

* **Rule:** If the LLM infers that a database schema changed, but the diff only shows a UI update, it must **not** mention the database schema.
* **Enforcement:** Prompts are structured with strict "Base your answer ONLY on the provided diffs" clauses.

## 2. Intent Over Implementation

The LLM's primary job is to extract the *why*, not the *what*.
* **Bad Output:** "The developer added a `return true` statement on line 45 of `auth.ts`."
* **Good Output:** "The developer bypassed the MFA check in `auth.ts` temporarily."
* **Rule:** The LLM must summarize the architectural or feature-level intent of the change. The structural extraction already handled the line-by-line syntax changes.

## 3. Strict JSON Schema Adherence

The LLM must output valid JSON conforming perfectly to the `SemanticDiff` schema defined in `DATA_FLOW.md`.
* **Rule:** Use JSON mode (or structured outputs) available in modern LLM APIs to enforce the schema.
* **Fallback:** If the LLM returns malformed JSON, the `semantic-engine` must retry exactly once. If it fails again, it emits an empty semantic summary to prevent blocking the pipeline.

## 4. Token Conservation

ProjectMind is designed to save tokens for the primary coding agent. Therefore, the summaries generated by ProjectMind's internal LLM must be ruthlessly concise.
* **Rule:** `intent_summary` fields are limited to 2 sentences max.
* **Rule:** `architectural_impact` must be a single sentence starting with a severity level (None, Low, Medium, High).

## 5. Stateless Inference

The local LLM inside ProjectMind does not have a "chat history". Every time `projectmind update` runs, the LLM is invoked as a zero-shot completion.
* **Rule:** Do not attempt to pass the entire `history.jsonl` into the LLM on every update. It will cause context explosion. Provide only the immediate diff.
