# Security Model

Phase 4.4 establishes the core security boundary of ProjectMind.

## Core Principle
**No action is executed without explicit authorization.** 
The ActionGraph generated by Phase 4.3 passes through the `DecisionEngine`. The engine aggregates feedback from four separate systems:
1. **ProtectionManager**: Hardcoded absolute rules for sensitive files (`.git`, `.env`).
2. **RiskGate**: Heuristics preventing `HIGH` and `CRITICAL` risk operations from running autonomously.
3. **PolicyEngine**: User/Project defined hierarchical access rules.
4. **PermissionSet**: Core granular permissions (e.g., `READ_REPOSITORY`, `WRITE_REPOSITORY`).

An action receives one of three verdicts:
- **ALLOW**: The executor may run this action automatically.
- **REQUIRE_APPROVAL**: The executor must halt and wait for human confirmation.
- **DENY**: The executor is forbidden from running this action.

The SLM has absolutely no authority in this boundary. It cannot grant itself permissions or bypass the Policy Engine.
